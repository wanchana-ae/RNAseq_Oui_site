📈 RNAseq Oui: DESeq2 Analysis v4 — คืน DC3/DN3 กลับมา (13 samples, trimmed)

Project: RNAseq_Oui
Status: Done

🔍 เหตุผลที่วิเคราะห์ใหม่

อาจารย์สั่งให้กลับไปใช้ตัวอย่างครบ 3 ซ้ำ ในทุกกลุ่ม (คืน DC3 และ DN3 ที่เคยตัดออกใน v2/v3 เพราะเป็น PCA outlier) โดยยังคงใช้ trimmed reads (fastp + HISAT2 v2) เหมือน v3

Version Samples Input Reads หมายเหตุ
v1 13 samples Raw reads baseline
v2 11 samples (ตัด DC3/DN3) Raw reads ลด noise จาก outlier
v3 11 samples (ตัด DC3/DN3) Trimmed reads ผลหลักเดิม
v4 13 samples (คืน DC3/DN3) Trimmed reads ตามคำสั่งอาจารย์

สำคัญ: ไม่ต้องรัน fastp/HISAT2/StringTie/prepDE ใหม่ — ตรวจสอบไฟล์ต้นฉบับแล้วพบว่า gene_count_matrix_2.csv (จาก v3) มีคอลัมน์ trimmed data ของ DC3/DN3 อยู่แล้ว (DC3 alignment 94.05%, DN3 93.20% หลัง trim) เพียงแค่สร้าง sample_list_DESeq2_v4.txt ใหม่ให้มีครบ 13 samples แล้วรัน DESeq2.R ใหม่

🧪 Experimental Design

13 samples: PNC1, PNC2, PN3 (PTT1_Control) / PC1–PC4 (PTT1_Compact) / DN1, DN2, DN3 (Dharia_Control) / DC1, DC2, DC3 (Dharia_Compact)

🛠️ Compute Resources

  • Tool: DESeq2 (R)
  • Input: gene_count_matrix_2.csv (13 samples, trimmed — คัดลอกจาก v3), sample_list_DESeq2_v4.txt
  • Design: ~ Conditon
  • Script: 📊 DESeq2.R R

⚠️ QC — พบสัญญาณสำคัญก่อนดูผล DEG

PCA plot (PCA_plot_vsd_with_Rep.pdf): PC1 (65% variance) ยังคงแยกกลุ่ม PTT1 vs Dharia ได้ชัดเจน แต่ DC3 และ DN3 (rep3) ยังคงแยกตัวออกจาก replicate คู่ของตัวเองไปทาง PC2 แม้ trim แล้ว alignment rate จะดีขึ้นมาอยู่ในเกณฑ์ปกติ (93–94%) แล้วก็ตาม

Sample Distance Heatmap: พบว่า Dharia_Control-3 (DN3) กับ Dharia_Compact-3 (DC3) จับกลุ่มกันเองก่อน แล้วถึงไปรวมกับ replicate 1,2 ของ treatment ตัวเอง (ซึ่ง DC1/DC2 จับคู่กันแน่น และ DN1/DN2 จับคู่กันแน่น) — สัญญาณนี้ชี้ไปทาง batch effect ที่เป็นไปได้ (เช่น rep3 ของ Dharia ทั้งคู่เตรียม/สกัดคนละรอบกับ rep1,2) มากกว่าจะเป็นแค่ noise สุ่ม

สรุป: สาเหตุที่ DC3/DN3 หลุดจากกลุ่มไม่ใช่ปัญหาคุณภาพ read (fastp แก้ตรงนั้นแล้ว) แต่น่าจะเป็น biological/batch variation จริงของตัวอย่างนั้น
